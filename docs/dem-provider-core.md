# DEM Provider共通基盤（PR 1）

`config.ts`の`DemProvider`を`createElevationSampler(provider, loader)`へ渡す。
既存のレベル配列による呼び出しもGSI互換として残す。

ProviderはID、表示名、出典・規約・帰属リンク、提供範囲、取得レベル、欠測時の方針を持つ。
取得レベルはURL、ズーム、タイルサイズ、エンコードを指定する。
`bounds`は提供範囲の外枠であり、範囲内の全タイルの存在を保証しない。

```text
クリック／ルート点 → Provider設定 → 画素中心の双線形補間
                                  ↓ 最大4画素（隣接タイルにも対応）
                           共通ローダー → fetch → 画像復号 → Float32Array
                                  ↑ Promise共有・LRUキャッシュ
```

GSIはDEM5A/z15/256pxを優先し、404または欠測ならDEM/z14/256pxを使う。
通信・HTTP・画像復号エラーを欠測へ変換せず、低解像度へ進まない。
4画素が揃わない場合は従来と同じ中心画素参照を試す。

キャッシュキーはProvider、レベル、URL、サイズ、エンコード、z/x/yを含む。
完了結果は全体32MiB・128件のLRU、404は60秒、エラーは保存しない。
取得と復号は最大6件同時。容量は標高配列の容量であり、ブラウザ全体の使用メモリではない。
取得中Promiseは共有されるため、利用側の中断によって他の利用者の取得を止めない。

計測セッションは新規取得数、キャッシュ参照数、Promise共有数、取得本文サイズを記録する。
HTTPキャッシュからの応答もfetch呼び出しに数える。本文サイズはネットワーク転送量と異なる。
画像は色変換・拡縮をせず、完全不透明な画素のみ復号する。

検証: 既存42テストに加え、キャッシュ分離・LRU・404期限・エラー再試行・取得並列数、
256/512px座標変換、4タイル境界補間、Providerのエラー保持を単体テストする。
ブラウザ実通信とMapterhorn追加はPR 2で検証する。
